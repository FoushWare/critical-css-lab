🎬 الحلقة ٦

هل Next.js SSR بيلغي احتياجك لـ Critical CSS؟

في الحلقة ٤ اكتشفنا إن React CSR عنده مشكلة إضافية: الـ JS لازم يشتغل الأول قبل ما أي حاجة تتعرض. Next.js بيحل مشكلة الـ JS دي بالـ SSR — بس هل ده معناه إن مشكلة الـ CSS اتحلت هي كمان؟ جهّزنا نسختين حقيقيتين بـ Next.js 16 و Tailwind CSS 4 نقارن بيهم.

🧠 الفرق الأساسي

SSR بيحل مشكلة الـ JS، مش مشكلة الـ CSS

في CSR (React عادي)، المتصفح لازم يجيب الـ JS Bundle، يشغّله، وبعدين يبني الـ HTML بنفسه — فمفيش حاجة تتعرض قبل كل ده. في SSR، السيرفر بيبعت HTML كامل وجاهز من الأول. لكن السؤال الحقيقي مش "الـ HTML وصل ولا لأ؟" — السؤال هو "الـ CSS اللي بيلوّن الـ HTML ده وصل ولا لأ؟"

⚠️
الـ <link rel="stylesheet"> اللي Next.js بيحقنه في الـ <head> بيفضل Render-blocking بنفس الشكل، حتى لو الـ HTML نفسه كامل وموجود. المتصفح لسه مش هيرسم قبل ما يوصله ويحلّله — SSR غيّر مين اللي بيبني الـ HTML، مش إمتى الـ CSS بيوصل.

⚙️ الإعداد

سطر واحد بيفرق: experimental.optimizeCss

في نسخة الـ After، الإضافة الوحيدة كانت في next.config.js:

// next.config.js /** @type {import('next').NextConfig} */ const nextConfig = { experimental: { optimizeCss: true, }, }; module.exports = nextConfig;
✅
وقت الـ Build/SSR، Next.js بياخد الـ CSS الناتج من Tailwind ويحوّل الـ <link> لـ <style> Inline جوه كل صفحة — أوتوماتيك، من غير Build Script إضافي من عندك.
⚠️
لكن انتبه لتفصيلتين: الفلاج ده لسه experimental ومسمّاه وسلوكه بيختلف بين إصدارات Next.js (فيه فلاج تاني اسمه inlineCss في الـ App Router أحدث). وتقنيًا هو بيعمل Inline لكل الـ CSS مش بس الـ "Critical" above-the-fold — يعني قريب أكتر من استراتيجية "Inline الكل" اللي ناقشناها قبل كده، مش من الـ Critical Extraction اليدوي بالظبط. راجع Docs النسخة اللي شغّال بيها قبل ما تعتمد عليه.

يعني الإجابة على سؤال العنوان: لأ، SSR لوحده مش بديل عن Critical CSS — هو بيحل مشكلة تانية خالص (JS Blocking في CSR). لسه محتاج حل صريح لمشكلة الـ CSS، سواء يدوي أو Built-in زي optimizeCss. وبما إن الـ SSR بيبعت HTML كامل (أكبر من الـ Shell البسيط بتاع SPA)، قاعدة الـ 14 KB بتبقى أضيق: لازم الـ Critical CSS المحقون يفضل صغير عشان الصفحة كلها متعدّيش الميزانية دي في أول Packet.
