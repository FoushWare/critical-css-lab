استراتيجيات تحميل CSS الخمسة

فيه أكتر من طريقة تخلّي المتصفح يحمّل الـ CSS، ومش كلهم بيمنعوا الرسم بنفس الشكل. جرّبنا 5 استراتيجيات مختلفة، كل واحدة شغّالة على بورت لوحدها، عشان نقارن سلوك كل طريقة بالظبط.

1️⃣ الاستراتيجية الأولى — الأساس Port 8090

Blocking CSS — الطريقة التقليدية

أبسط طريقة، وهي اللي بيستخدمها معظم الناس من غير ما ياخدوا بالهم. المتصفح بيوقف الرسم كامل لحد ما يجيب الملف ويحلّله.

<head> <link rel="stylesheet" href="styles.css"> </head>
Render-blocking: Yes FOUC: مستحيل تعقيد: صفر
⚠️
المتصفح مش هيرسم أي بكسل قبل ما الـ CSS يوصل ويتحلّل بالكامل. في الشبكات البطيئة، ده بيبان كصفحة بيضا واقفة.
2️⃣ الاستراتيجية التانية — الحيلة القديمة Port 8091

Media Attribute Trick — media="print"

حيلة قديمة ومعروفة (من Filament Group): تخلّي المتصفح يفتكر إن الملف مخصّص للطباعة بس، فبيحمّله بأولوية منخفضة من غير ما يمنع الرسم. لما التحميل يخلص، الـ JavaScript بيغيّر الـ media لـ all عشان يتطبّق فعليًا.

<link rel="stylesheet" href="styles.css" media="print" onload="this.media='all'"> <!-- Fallback لو الـ JS متعطل --> <noscript> <link rel="stylesheet" href="styles.css"> </noscript>
Render-blocking: No FOUC: ممكن يحصل للحظة تعقيد: يحتاج noscript Fallback
💡
حل قديم وموثوق جدًا، ومتوافق مع كل المتصفحات تقريبًا حتى القديمة منها — عيبه إنه شكله "Hack" مش API واضح الغرض منه.
3️⃣ الاستراتيجية التالتة — الأحدث والأنضف Port 8092

Preload CSS — rel="preload"

بتقول للمتصفح "حمّل الملف ده بأولوية عالية بدري، بس متطبقهوش دلوقتي". لما يخلص تحميل، بتحوّل الـ rel لـ stylesheet عشان يتفعّل.

<link rel="preload" href="styles.css" as="style" onload="this.onload=null;this.rel='stylesheet'"> <noscript> <link rel="stylesheet" href="styles.css"> </noscript>
Render-blocking: No FOUC: ممكن يحصل للحظة تعقيد: بسيط، API واضح
✅
ده الاختيار الافتراضي الجيد لمعظم الحالات: بيحمّل الملف بأولوية عالية زي الـ Blocking، بس من غير ما يوقف الرسم. مدعوم في كل المتصفحات الحديثة.
4️⃣ الاستراتيجية الرابعة — من غير Link خالص Port 8093

Async Loading via JavaScript

مفيش <link> في الـ HTML أصلًا. الـ JavaScript هو اللي بيبني الـ Element ويضيفه للصفحة وقت التنفيذ.

<script> const link = document.createElement('link'); link.rel = 'stylesheet'; link.href = 'styles.css'; document.head.appendChild(link); </script>
Render-blocking: No FOUC: خطر عالي تعقيد: يعتمد كليًا على JS
⚠️
مفيش <noscript> Fallback طبيعي هنا — لو الـ JS اتعطل أو اتأخر، الصفحة ممكن تفضل من غير ستايل خالص. مناسبة أكتر لتطبيقات SPA أصلًا معتمدة على JS بشكل كامل.
5️⃣ الاستراتيجية الخامسة — أفضل ممارسة Port 8094

Critical CSS + Async — الجمع بين الاتنين

هنا بتجمع بين حاجتين: <style> Inline فيه الـ Critical subset (بيرسم فورًا من غير أي Request)، بالإضافة لباقي الملف بيتحمّل Async بنفس أسلوب الـ Preload.

Inline <style> critical فقط
→
Paint فوري 🎨
→
Preload باقي الملف
→
Swap → stylesheet
<head> <!-- Critical CSS: above-the-fold بس --> <style> .header{ ... } .hero{ ... } </style> <!-- الباقي: Preload + Swap --> <link rel="preload" href="styles.css" as="style" onload="this.onload=null;this.rel='stylesheet'"> <noscript><link rel="stylesheet" href="styles.css"></noscript> </head>
Render-blocking: No FOUC: أقل خطر (above-the-fold متلوّن من الأول) تعقيد: الأعلى — محتاج Build step لاستخراج الـ Critical
✅
أحسن نتيجة FCP في الخمس استراتيجيات، بس التكلفة هي التعقيد: لازم Build Pipeline يستخرج الـ Critical subset، ويفضل محدث كل ما التصميم يتغيّر — زي ما شفنا في الحلقة اللي فاتت عن Tailwind.
