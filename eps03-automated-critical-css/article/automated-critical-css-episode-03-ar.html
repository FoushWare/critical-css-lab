🎬 الحلقة ٣

أتمتة Critical CSS بالأدوات

الحلقة اللي فاتت شفنا إن الطريقة اليدوية تتعب بسرعة. دلوقتي هنشوف إزاي أدوات زي critical وPenthouse وbeasties بتعمل نفس الشغل أوتوماتيك — وبدقة أعلى غالبًا من العين المجردة.

🧠 إزاي الأدوات دي شغالة تحت السطح

Headless Browser بيرسم الصفحة فعليًا ويسجّل النتيجة

الأدوات دي مش بتحلل الـ CSS نصيًا — بتفتح الصفحة فعليًا جوه Headless Chrome (زي Puppeteer)، بحجم Viewport محدد، وبتسجّل كل الـ Rules اللي فعلًا اتطبّقت على أي عنصر ظاهر. الفرق عن Coverage Tab إن ده بيحصل تلقائي لكل صفحة في الـ Build، من غير تدخل يدوي.

💻 التطبيق — critical

مثال عملي بأشهر أداة Node.js

// npm i -D critical // generate-critical.js import { generate } from "critical"; await generate({ base: "dist/", src: "index.html", target: "index.html", css: ["dist/styles.css"], inline: true, width: 375, // Viewport موبايل height: 667, });
✅
ممكن كمان تدّي الأداة أكتر من Viewport واحد (موبايل + Desktop) في نفس التشغيلة، فبتاخد Union الـ Rules من الاتنين — ده بيحل مشكلة "Above-the-fold بيختلف حسب الشاشة" اللي واجهتنا في الطريقة اليدوية.

🔍 حدود الأتمتة

الأدوات مش سحر — لسه فيها عيوب

⚠️
محتوى Dynamic: لو عنصر بيظهر بعد تفاعل (Modal، Dropdown، Tab تاني)، الأداة مش هتلاقيه "ظاهر" وقت الـ Scan، فالـ Classes بتاعته مش هتتحط في الـ Critical subset — يعني أول ما يظهر، هيبان من غير ستايل للحظة.
⚠️
وقت الـ Build: فتح Headless Chrome لكل صفحة بياخد وقت — على موقع فيه مئات الصفحات، ده ممكن يضيف دقايق حقيقية على الـ CI/CD Pipeline.
