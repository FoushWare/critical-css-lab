ليه الـ CSS بيوقف رسم الصفحة أصلًا؟

قبل ما نتكلم عن حلول زي Critical CSS، لازم نفهم المشكلة الأساسية: ليه المتصفح بيرفض يرسم أي حاجة لحد ما الـ CSS يوصل؟ ده مش Bug — ده قرار متعمّد. الحلقة دي هي نقطة البداية لسلسلة كاملة عن استراتيجيات تحميل CSS.

🧠 المسار الحرج للرسم — Critical Rendering Path

من الـ HTML لحد أول بكسل على الشاشة

المتصفح بيبني شجرتين منفصلتين: DOM من الـ HTML، وCSSOM من الـ CSS. المشكلة إن المتصفح مش بيقدر يبدأ يرسم إلا لما الشجرتين يتدمجوا في Render Tree — وده معناه لازم يستنى الـ CSSOM يخلص أولًا.

💡
الـ HTML Parsing ممكن يكمل ويبني DOM كامل وهو مستني الـ CSS — المتصفح شاطر كفاية إنه يعمل الحاجتين مع بعض. لكن مرحلة الـ Paint نفسها واقفة تمامًا لحد ما الـ CSSOM يخلص.
🎯 السبب الحقيقي

ده مش تقصير من المتصفح — ده حماية من الـ FOUC

لو المتصفح رسم الصفحة بالـ HTML بس وبعدين لوّنها لما الـ CSS يوصل، هتشوف FOUC (Flash of Unstyled Content) — الصفحة تظهر شكلها الافتراضي (نص أسود، Times New Roman) للحظة، وبعدين "تقفز" للتصميم الحقيقي. كل المتصفحات الحديثة قررت تمنع الرسم بدل ما تسيب المستخدم يشوف القفزة دي.

بدون الحماية دي: FOUC مضمون مع الحماية: صفحة بيضا بدل قفزة بصرية
🔍 النقطة اللي هتلفت نظرك

الـ CSS مش بس بيوقف الرسم — بيوقف الـ JavaScript كمان

تفصيلة كتير من الناس مش واخدين بالهم منها: أي <script> عادي (من غير async أو defer) جاي بعد <link rel="stylesheet"> في الـ HTML، مش هيتنفذ إلا بعد ما الـ CSSOM يخلص بناء. السبب: الـ JS ممكن يسأل عن Computed Styles (زي getComputedStyle)، فالمتصفح لازم يضمن إن الـ CSSOM جاهز قبل ما ينفذ أي كود ممكن يحتاجه.

<head> <link rel="stylesheet" href="styles.css"> <!-- السكريبت ده مش هيتنفذ إلا بعد ما styles.css يوصل ويتحلل بالكامل --> <script src="app.js"></script> </head>
⚠️
يعني ملف CSS بطيء مش بس بيأخر الرسم — ممكن يأخر أي منطق JS مهم كان المفروض يشتغل بدري، حتى لو الـ JS نفسه مش بيلمس CSS خالص.
