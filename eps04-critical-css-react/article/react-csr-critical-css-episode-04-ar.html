React وCritical CSS — مشكلة إضافية

لحد دلوقتي كنا بنتكلم عن صفحات HTML عادية. لكن في React (Client-Side Rendering)، فيه مشكلة تانية بتتحط فوق مشكلة الـ CSS: الـ HTML نفسه فاضي لحد ما JavaScript يشتغل. يبقى إيه معنى "Above-the-fold" أصلًا لو مفيش محتوى موجود أصلًا؟

🧠 المشكلة المضاعفة

CSR = JS Blocking + CSS Blocking مع بعض

في صفحة HTML عادية، المحتوى موجود في الـ HTML من الأول — بس شكله مش نهائي لحد ما الـ CSS يوصل. في React CSR، الـ HTML الأولي عبارة عن <div id="root"></div> فاضي تمامًا. المحتوى نفسه مش موجود لحد ما الـ JS Bundle يتحمّل، يتنفذ، وReact يرسم الـ DOM.

HTML Shell <div id="root">
→
JS Bundle تحميل + تنفيذ
→
React Render DOM اتبنى دلوقتي بس
→
CSS لسه محتاج يتلوّن
→
Paint 🎨
⚠️
يعني في CSR، حتى لو الـ CSS وصل فورًا، المستخدم لسه هيشوف صفحة فاضية لحد ما الـ JS يخلص شغله. الـ Critical CSS مش هيسرّع حاجة هنا لو المشكلة الأساسية هي JS مش CSS.
🎯 يبقى Critical CSS يستهدف إيه في React؟

الحل: Critical CSS لـ Loading State مش للمحتوى النهائي

بما إن المحتوى الحقيقي مش موجود قبل الـ Hydration، الاستخدام العملي لـ Critical CSS هنا بيكون لتلوين حاجة بسيطة موجودة في الـ HTML الأولي فعلًا — زي Skeleton Screen أو Spinner — عشان المستخدم مايشوفش صفحة بيضا فاضية تمامًا وهو مستني JS.

<body> <style> /* Critical: بس لتلوين الـ Loading Skeleton */ .skeleton{ background: #1a2030; animation: pulse 1.5s infinite; } </style> <div id="root"> <div class="skeleton"></div> <!-- ظاهر قبل React خالص --> </div> <script src="bundle.js"></script> </body>
