هل الـ CSS بيأثر على الأداء زي الـ JavaScript؟

قبل ما نبدأ الحلقة الأولى، خلينا نتفق على السبب اللي خلانا نعمل السلسلة دي أصلًا.

🟨 الجزء اللي كل حد بيتكلم عنه

لما بنتكلم على الـ Performance، دايمًا بنتكلم على الـ JavaScript

وده مفهوم — الـ JS فعلًا بيستهلك وقت معالجة، وبيكبر بسرعة. عشان كده احنا معتادين نعمل حاجات زي:

▸Code Splitting — نقسّم الـ Bundle الكبير لأجزاء أصغر تتحمّل عند الحاجة
▸Lazy Loading — نأجّل تحميل المكونات اللي مش ظاهرة فورًا
▸Tree Shaking — نشيل أي كود مش مستخدم قبل ما نبعت الـ Bundle
▸defer / async — نمنع السكريبتات من إنها توقف تحميل باقي الصفحة
▸Minification — نقلل حجم كل كيلوبايت زيادة زي ما بنراقب فلوسنا

كل ده صح، وكل ده مهم. المشكلة مش في الاهتمام بالـ JS — المشكلة إن الاهتمام ده بيبقى الاهتمام الوحيد.

🟩 الجزء اللي نادرًا ما بنتكلم عنه

طب الـ CSS بتاعك بيوقف رسم الصفحة قد إيه؟

الحقيقة إن المتصفح مش بس بينتظر الـ JavaScript — بينتظر الـ CSS كمان، وبطريقة أعمق من اللي إحنا فاكرينها. المتصفح بالحرفي بيرفض يرسم أي بكسل على الشاشة لحد ما يجيب ملف الـ CSS، يحلّله، ويبني منه شجرة كاملة.

💡
صفحة بيضا واقفة مش دايمًا بسبب JS بطيء — أحيانًا كتير السبب إن ملف CSS واحد لسه ما وصلش.
