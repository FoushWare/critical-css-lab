📊 How to View Network Waterfall

Use Chrome DevTools to see the actual network waterfall and how CSS blocks rendering.

1

Open Chrome DevTools

Press F12 or Ctrl+Shift+I (Windows) / Cmd+Option+I (Mac)

2

Go to Network Tab

Click on the "Network" tab in DevTools

3

Disable Cache

Check the "☑ Disable cache" checkbox

4

Set Network Throttling

Click the dropdown and select "Slow 3G" to simulate slow network

5

Reload the Page

Press F5 or click the reload button

6

Observe the Waterfall

Look for styles.css - notice how it blocks rendering (red bar)

🔍 What to Look For:
  • Waterfall timeline - See the sequential loading of resources
  • Red blocking bar - CSS blocking other resources
  • Transfer size - Amount of data transferred (~20KB)
  • Time - How long CSS takes to download and parse
💡 Pro Tip: Try "Fast 3G" vs "Slow 3G" to see how network speed affects the render-blocking impact.

⚡ How to Measure Performance

Use Chrome DevTools Performance panel to measure actual page performance metrics.

1

Open Chrome DevTools

Press F12 or Ctrl+Shift+I (Windows) / Cmd+Option+I (Mac)

2

Go to Performance Tab

Click on the "Performance" tab in DevTools

3

Set Network Throttling

In Network tab, set throttling to "Slow 3G" for realistic measurements

4

Start Recording

Click the "Record" button (circle icon) or press Ctrl+E / Cmd+E

5

Reload the Page

Refresh the page while recording

6

Stop Recording

Click the "Stop" button (square icon) after page loads

7

Analyze Results

Look at the timeline and metrics in the bottom panel

🔍 Key Metrics to Check:
  • FCP (First Contentful Paint) - When content first appears
  • LCP (Largest Contentful Paint) - When main content is visible
  • Parse CSS - Time spent parsing the stylesheet
  • Recalculate Style - Time spent applying styles
💡 Pro Tip: Hover over the timeline to see exact timing for each stage. Look for the gap between HTML download and first paint - that's your CSS blocking time.

🎯 What is Critical CSS?

The Problem

When a browser loads your page, it must download and parse your entire CSS stylesheet before it can render any content. This includes styles for content the user can't even see yet (like footers, modals, or below-the-fold content).

The Solution: Critical CSS

Critical CSS is the minimum set of styles needed to render the above-the-fold content - what users see initially without scrolling. By inlining these critical styles directly in your HTML, the browser can render content immediately while loading the rest of your CSS asynchronously.

How It Works

❌ Before (Normal CSS)

<link rel="stylesheet" href="styles.css"> <!-- Browser waits for ENTIRE stylesheet --> <!-- 20KB of CSS blocks rendering --> <!-- User sees blank screen for 2.8s -->

✅ After (Critical CSS)

<style> /* Critical CSS - only 8KB */ /* Header, hero, navigation */ </style> <!-- Content renders immediately! --> <link rel="preload" as="style" onload="this.onload=null;this.rel='stylesheet'" href="styles.css">

The Trade-offs

✅ Benefits

  • Faster initial render
  • Better perceived performance
  • Improved Core Web Vitals
  • Better user experience on slow networks

⚠️ Costs

  • Increased HTML size
  • CSS duplication (critical + full)
  • Build complexity
  • Maintenance overhead
💡 When to Use Critical CSS: Most effective for content-heavy sites with significant below-the-fold content, users on slow networks, or when Core Web Vitals are a priority. For simple sites or single-page apps, the overhead may not be worth it.

About This Project

The Critical CSS Lab

This project is a hands-on investigation into Critical CSS and its impact on web performance. We build real pages, measure their performance, and apply optimizations to understand the actual benefits and trade-offs.

Unlike toy demos, we use realistic pages with substantial CSS to see how Critical CSS performs in production-like scenarios. Our goal is to provide honest, data-driven insights that help you make informed decisions about CSS optimization.

Throughout this series, we'll explore Critical CSS in different environments: vanilla HTML/CSS, React, Tailwind, and Next.js, to understand how the approach changes with modern frameworks.
